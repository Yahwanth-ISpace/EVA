Retry policy and completion criteria Assumptions, dependencies, decisions, and open items Key stakeholders, teams, and responsibilities Background & Context As part of the eligibility and benefits verification process for Dental offices, deployed agents contact insurance companies via phones to verify dental benefits for patients. The verified information supports dental clients and is captured in Sabrina, which is used to collect and manage insurance benefit-related data. This initiative introduces an AI Calling Agent ( Sabrina Verification Agent ) as an alternate execution channel for insurance benefit verification, mimicking the existing manual calling procedure, with tight integration to Sabrina. Note: Sabrina Voice Agent will be utilized for calling Insurance companies across all it’s modules Problem Statement The existing verification workflow depends heavily on human calling agents to perform repetitive benefit checks, meaning we currently need many people to sustain volumes. By introducing Sabrina Verification Agent for eligible cases, we improve consistency of captured benefit data and reserve human effort for exceptions, complex scenarios, and extended data capture beyond the Phase 1 field set. 4 Sabrina Verification Agent Sabrina serves as the primary system of record for managing all appointments. Sabrina initially checks patient benefit details in Dental Exchange. If benefit details are found, Sabrina submits the appointment. If benefit details are not found, the Sabrina Verification Agent initiates a call to the insurance provider. The Sabrina Verification Agent, integrated with Sabrina, places outbound calls to insurance companies. The agent navigates IVR flows or connects with representatives, captures Phase 1 existing plan benefit details, and writes the collected information and call status back to Sabrina. Any exceptions will be sent to experienced agent to take over. 5. Current Process (As-Is-calling) We receive appointments through BCP file from all the clients. Appointments received through the BCP file are loaded into Sabrina. Patient eligibility can be verified through three methods: via insurance websites, through fax, or by calling insurance companies. As this document focuses on calling automation, only the calling process is described here. Supervisors assign appointments to calling users through Sabrina. For certain clients, appointments are auto assigned based on predefined business logic. Agents contact insurance payers to perform eligibility verification for the assigned appointments based on the appointment dates. Calls are placed to the respective insurance payers using the contact details available in Sabrina, as per the appointment data. Agents navigate through the IVR by selecting the required options to connect with an insurance representative. During the call, the insurance representative authenticates the provider by validating the Facility Tax ID and NPI. Patient details, including Name, Date of Birth (DOB), and Insurance ID, are verified. First, the initial six mandatory fields are verified to determine whether the insurance plan exists in Sabrina. The six mandatory fields include: Preventive (%), Basic (%), Major (%), Yearly Maximum ($), Individual Deductible ($), and Family Deductible ($). If the plan exists in Sabrina, a limited set of benefit fields is captured; if the plan does not exist, a full plan benefits capture is performed. All verified eligibility and benefit data are stored in Sabrina. Target Process (To-Be) Using Sabrina Verification Agent + Sabrina Appointments are received from clients and managed in Sabrina. Sabrina sends case data to Sabrina Verification Agent via API, which serves as the initiation payload for Sabrina Verification Agent processing. Sabrina Verification Agent executes an outbound call and follows the payer‑specific IVR and representative workflow for the selected pilot payer. Sabrina Verification Agent navigates through the IVR by selecting the required options to connect with an insurance representative. During the call, Sabrina Verification Agent verifies the provider by providing the Facility Tax ID and NPI. Sabrina Verification Agent captures the standardized Phase 1 field set, consisting of 25 fields. Sabrina Verification Agent writes the captured data along with the call status back to Sabrina via API. The call is considered complete for Phase 1 once all 25 plan fields are captured. Sabrina then determines whether the record corresponds to an existing plan or a new plan. If it is an existing plan, Sabrina selects the plan, populates all captured fields, and submits the form. If it is a new plan, Sabrina routes the appointment to a separate queue along with the captured details. The overall call is considered complete once all required plan fields are captured. All remaining additional fields are captured by a human user to complete the remaining data capture. For existing plans, any benefit fields that Sabrina Verification Agent cannot collect will be routed to the exception queue. Any other exceptions identified during processing will be reviewed, and feedback will be provided accordingly. Tenant ID: - Client details. Appointment details, double click on the object to open. Field Capture & Completion Criteria (Phase 1) Sabrina Verification Agent ’s scope in Phase 1 is limited to capturing a standardized set of existing plan per call. The final field list will be provided/approved by the Operations team and will be mapped to Sabrina fields. 9A Completion Criteria A call is marked “Completed” when all existing fields are captured as per input Json file. If Sabrina Verification Agent cannot write back to Sabrina due to validation/API errors, the call is marked “Incomplete” and the case remains with Operations for follow-up. 9B Retry Policy Any call disconnected after connecting with an insurance representative, before collecting complete information, will be treated as a call drop. Maximum of 2(TBD) call attempts per case. Handling Missing, Incomplete, or Ambiguous Information If a payer does not provide required values or the response is unclear, Sabrina Verification Agent will: Record the best available structured outcome (e.g., Not Provided, Unknown, Not Applicable). Capture supporting notes where available (For later Sabrina Verification Agent luation). Continue to complete the existing fields capture where possible; if completion criteria cannot be met, return status to Sabrina for Operations follow-up. Assumptions, Dependencies Assumptions Sabrina remains the system of records and provides API access for Sabrina Verification Agent to read case context and write back captured results. Operations will provide the existing field list and confirm mapping/validations with Sabrina and Sabrina Verification Agent teams. Pilot will operate using US time zone scheduling context. Dependencies Sabrina API endpoint and field mapping. Handshake/confirmation of Sabrina validations and acceptable status values for missing data. Open Item Comprehensive mapping of existing data fields to corresponding questions, enabling Sabrina Verification Agent to accurately understand and navigate the call flow.
